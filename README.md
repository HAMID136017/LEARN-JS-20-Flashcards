# ۲۰ فلش‌کارت جاوااسکریپت برای باگ‌بانتی

مرور درس‌ها تا این نقطه: مبانی، شرط و تابع، آرایه و شیء، DOM، درخواست و پاسخ API. روی هر سؤال کلیک کن تا جواب را ببینی. هر کارت یک پاسخ کوتاه و یک دلیل یا کاربرد دارد.

<details><summary>۱. متغیر چه کاری می‌کند؟</summary>

**پاسخ:** مقداری را با نام نگه می‌دارد تا دوباره استفاده کنیم. **کاربرد:** نگه‌داشتن شناسه یا پاسخ یک درخواست.

</details>

<details><summary>۲. فرق `let` و `const` چیست؟</summary>

**پاسخ:** مقدارِ متغیرِ `let` را می‌توان دوباره تعیین کرد؛ مقدارِ متغیرِ `const` را نه. **دلیل:** جلوی تغییر ناخواستهٔ نام‌هایی را می‌گیرد که قرار است ثابت بمانند.

</details>

<details><summary>۳. فرق `"42"` و `42` چیست؟</summary>

**پاسخ:** اولی متن و دومی عدد است. **کاربرد:** `Number("42") + 1` برابر `43` است، ولی `"42" + 1` برابر `"421"`.

</details>

<details><summary>۴. فرق `undefined` و `null` چیست؟</summary>

**پاسخ:** `undefined` یعنی مقداری نگرفته یا وجود ندارد؛ `null` یعنی عمداً «بدون مقدار» تعیین شده است. **کاربرد:** در پاسخ‌های API و پارامترهای آدرس این تفاوت را بررسی کن.

</details>

<details><summary>۵. `NaN` چه زمانی دیده می‌شود؟</summary>

**پاسخ:** وقتی تبدیل یا محاسبهٔ عددی نتیجهٔ عدد معتبر ندهد؛ مثل `Number("200tl")`. **کاربرد:** ورودی عددی را پیش از استفاده بررسی کن؛ `typeof NaN` با وجود نامش `"number"` است.

</details>

<details><summary>۶. `===` چه چیزی را مقایسه می‌کند؟</summary>

**پاسخ:** هم مقدار و هم نوع را؛ `"42" === 42` نادرست است. **دلیل:** از برابر شمردن تصادفی متن و عدد جلوگیری می‌کند.

</details>

<details><summary>۷. فرق `&&` و `||` در شرط چیست؟</summary>

**پاسخ:** `&&` درست‌بودن هر دو شرط را می‌خواهد؛ `||` درست‌بودن یکی را کافی می‌داند. **کاربرد:** خواندن شرط‌های نمایش دکمه یا اجازهٔ ویرایش؛ شرطِ مرورگر مجوز سرور را ثابت نمی‌کند.

</details>

<details><summary>۸. تابع و پارامتر چه هستند؟</summary>

**پاسخ:** تابع یک کارِ قابل تکرار است؛ پارامتر مقدار ورودی آن است. **مثال:** در `function checkRole(role) { ... }`، نام تابع `checkRole` و پارامتر `role` است.

</details>

<details><summary>۹. در آرایه، `find` چه می‌کند؟</summary>

**پاسخ:** اولین عضوِ مطابق شرط را برمی‌گرداند. **کاربرد:** پیدا کردن یک کاربر با شناسهٔ مشخص در فهرست؛ نتیجهٔ پیدا کردن در مرورگر به‌تنهایی مجوز دسترسی نیست.

</details>

<details><summary>۱۰. از `{"user":{"role":"editor"}}` چگونه نقش را می‌خوانیم؟</summary>

**پاسخ:** `data.user.role`. **دلیل:** `role` داخل `user` است؛ `data.role` در این ساختار `undefined` خواهد بود.

</details>

<details><summary>۱۱. فرق `JSON.stringify` و `response.json()` چیست؟</summary>

**پاسخ:** `JSON.stringify` دادهٔ جاوااسکریپت را برای **ارسال** به متن JSON تبدیل می‌کند؛ `response.json()` بدنهٔ JSON **دریافتی** را می‌خواند و به دادهٔ قابل استفاده تبدیل می‌کند.

</details>

<details><summary>۱۲. `document.querySelector("#nameBox")` چه می‌کند؟</summary>

**پاسخ:** عنصر دارای شناسهٔ `nameBox` را در صفحه پیدا می‌کند. **کاربرد:** بعداً متنش را بخوانیم یا تغییر دهیم؛ این خط درخواست شبکه نمی‌فرستد.

</details>

<details><summary>۱۳. فرق `textContent` و `innerHTML` چیست؟</summary>

**پاسخ:** اولی `<b>Sara</b>` را با خودِ علامت‌ها نشان می‌دهد؛ دومی آن را HTML تفسیر می‌کند و نام پررنگ می‌شود. **نکتهٔ امنیتی:** دادهٔ کاربر در `innerHTML` سرنخ بررسی XSS است؛ پررنگ‌شدن به‌تنهایی اجرای کد را ثابت نمی‌کند.

</details>

<details><summary>۱۴. `input.value.trim()` چه فایده‌ای دارد؟</summary>

**پاسخ:** متن کادر را می‌گیرد و فاصله‌های ابتدا و انتهای آن را حذف می‌کند. **کاربرد:** ورودیِ فقط شامل فاصله به `""` تبدیل می‌شود؛ سرور هم باید اعتبارسنجی خودش را انجام دهد.

</details>

<details><summary>۱۵. `addEventListener("click", showProfile)` چه زمانی تابع را اجرا می‌کند؟</summary>

**پاسخ:** هنگام کلیک روی عنصر. **کاربرد:** هنگام خواندن کد سایت می‌فهمیم کدام عمل کاربر باعث ارسال درخواست می‌شود.

</details>

<details><summary>۱۶. `fetch("/api/profile")` چه می‌کند؟</summary>

**پاسخ:** از مرورگر به مسیر `/api/profile` درخواست می‌فرستد؛ اگر روش تعیین نشود، پیش‌فرض `GET` است. **کاربرد:** پیدا کردن مسیرهای API در کد جاوااسکریپت.

</details>

<details><summary>۱۷. در درخواست `POST`، `method`، `headers` و `body` چه هستند؟</summary>

**پاسخ:** `method` روش درخواست است؛ `Content-Type: application/json` قالب بدنه را معرفی می‌کند؛ `body` دادهٔ ارسالی است. **مثال:** نام `Hamid` داخل بدنه می‌رود، نه هدر.

</details>

<details><summary>۱۸. فرق `response.status` و `response.ok` چیست؟</summary>

**پاسخ:** اولی کد وضعیت مثل `403` است؛ دومی برای وضعیت‌های ۲۰۰ تا ۲۹۹ `true` می‌شود. پاسخ `403` در `fetch` خودبه‌خود وارد `catch` نمی‌شود؛ خطای شبکه، خطای تجزیه یا `throw` این کار را می‌کند. **نکتهٔ امنیتی:** `200` یا `ok === true` اثبات انجام موفق عملیات نیست؛ اثر واقعی را هم ببین.

</details>

<details><summary>۱۹. چه زمانی `response.text()` و چه زمانی `response.json()`؟</summary>

**پاسخ:** برای متن ساده مثل `Not allowed` از `text()`؛ برای بدنهٔ JSON و خواندن فیلدی مثل `data.error` از `json()`. **دلیل:** `text()` حتی از JSON هم فقط رشتهٔ خام می‌سازد؛ `json()` روی متنِ JSON نامعتبر خطا می‌دهد.

</details>

<details><summary>۲۰. چه زمانی تغییر شناسه نشانهٔ آسیب‌پذیری IDOR است؟</summary>

**پاسخ:** وقتی حساب تو بدون مجوز به داده یا عملیات خصوصی حساب دیگری دسترسی پیدا کند. **کاربرد امنیتی:** صرف تغییر `/api/users/12` به `/api/users/13` یا دیدن پاسخ `200` کافی نیست؛ باید دسترسی واقعیِ بدون مجوز را ثابت کنی.

</details>

**روش مرور:** اول سؤال را جواب بده، سپس کارت را باز کن. موارد اشتباه را دوباره مرور کن. این کارت‌ها جای آزمون پایان جلسه را نمی‌گیرند.
